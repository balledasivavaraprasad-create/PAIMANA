# Landing Page Specification

## Goal

Create a premium product landing page that explains InfraBuild-AI without needing a verbal presentation.

The landing page is not a generic SaaS template. It should visually communicate that this is infrastructure intelligence built around continuous monitoring and agentic investigation.

## Header

Left:
- InfraBuild-AI logo/wordmark

Center/right navigation:
- Product
- Intelligence
- Analytics
- How It Works
- Technology

Actions:
- Sign in
- Request access / Open platform

Header becomes compact on scroll.

## Hero

### Eyebrow
`CONTINUOUS INFRASTRUCTURE INTELLIGENCE`

### Headline
Suggested direction:

> **Know what changed before it becomes a project crisis.**

Do not use generic phrases like “Revolutionizing infrastructure with AI.”

### Subheadline

Explain in 2–3 lines:

InfraBuild-AI continuously observes project state, predicts emerging cost and schedule risk, compares projects with relevant peers, investigates possible causes, and supports evidence-backed intervention.

### Hero visual

Create an interactive abstract “project intelligence field” rather than a generic stock image.

Possible visual:

- a dark infrastructure grid/map
- flowing project trajectories
- a highlighted project node crossing a risk boundary
- peer cohort nodes appearing around it
- an investigation pulse moving through evidence sources

Animation should be subtle and performant.

The hero visual should make the architecture legible without turning into an unreadable animated diagram.

## Proof strip

Immediately below hero show concise capability proof:

- Continuous monitoring
- Predictive risk
- Peer intelligence
- Agentic investigation
- Human-gated action
- Closed-loop outcomes

Do not fabricate customer logos or performance claims.

## Problem section

Title:

> **Infrastructure risk rarely appears all at once.**

Visual sequence:

Normal state → small divergence → accelerating risk → critical exposure

Explain that changes in progress, expenditure, milestones and schedule can accumulate before a project appears visibly critical.

## Product differentiator section

Title:

> **From project status to project intelligence.**

Show four columns:

### Predict
Cost, schedule, implementation risk.

### Contextualize
Peer cohort, benchmarks, historical trajectory.

### Investigate
Evidence-driven stateful agent.

### Act
Validated recommendations, approval and automated follow-up.

## “What changed?” section

This is a key visual centerpiece.

Show a realistic project timeline:

```text
Previous snapshot
↓
Progress 61%
Expenditure 64%
DPHIS 54

New snapshot
↓
Progress 59%
Expenditure 71%
DPHIS 72

Detected:
Cost-progress mismatch
Risk accelerating
```

Then show peer context:

```text
Peer median DPHIS: 46
Target DPHIS: 72
```

## Agentic investigation section

Show a clean animated loop:

```text
Event
→ Evidence needed
→ Tool selected
→ Observation
→ Hypothesis update
→ More evidence / conclude
```

Use only a few labels. Do not expose code.

## Peer intelligence section

Show:

Target project
vs
Peer cohort

Visualize:

- peer median
- target deviation
- trajectory difference
- similar project outcomes

The message is:

> A project is not understood in isolation.

## Analytics section

Show a miniature preview of the Analytics command center:

- portfolio risk trend
- cost vs schedule risk matrix
- event heatmap
- geographic distribution
- intervention outcomes

Charts should look like real Plotly output, not abstract decorative vectors.

## Governance section

Explain:

- Evidence lineage
- Uncertainty
- Human approval
- Audit trail
- Durable automation

This establishes trust without sounding legalistic.

## Product walkthrough

Use a 5-step interactive scroll sequence:

1. Monitor
2. Detect
3. Investigate
4. Decide
5. Learn

Each step updates a central visual.

## Final CTA

Suggested:

> **See the project before the problem becomes obvious.**

CTA:
`Open InfraBuild-AI`

Secondary:
`Explore the architecture`

## Footer

Include:
- product
- documentation
- contact
- sign in
- technology
- privacy
- terms

## Motion rules

Use:
- section entrance choreography
- scroll-linked progress indicator
- subtle graph transitions
- node highlighting
- number count-up only once when visible
- chart draw-on on first view

Avoid:
- continuous video backgrounds that compete with text
- full-page parallax
- excessive cursor effects
- bouncing cards
- excessive glow
